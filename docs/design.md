# PLC Server 设计文档

## 目标与边界

PLC Server 为 Siemens S7 的 DB 区提供按设备 ID 定位的读写服务。Elixir 进程可直接调用 `PlcServer`；外部进程用 HTTP/JSON 发起请求，用 MQTT 接收配置好的 DB 块变化事件。每台设备使用独立 C Port 调用 Snap7，避免将 PLC 通信放进 BEAM NIF。没有真实 PLC 时可以用 `--mock` 完成协议与接口联调。

当前支持 DB 原始字节、`bool`、16/32 位整数、32 位浮点、定长字符串和字节串；不提供 PLC 地址发现、符号寻址、事务写入或 MQTT 写命令。HTTP 和 MQTT 都是可选功能，未配置时不启动对应适配器。

## 核心决策

| 决策 | 实现与原因 |
| --- | --- |
| 一台 PLC 一个设备进程和 C Port | 隔离连接与超时故障，并在设备进程内协调写入。 |
| 原始字节为内部基础表示 | 同一读写路径上实现点位解码，避免协议层理解业务类型。 |
| 相同订阅键共享一个 Block | 复用轮询；订阅键为完整的 `{device_id, db, offset, length, interval_ms}`，点位订阅还包含点位配置。 |
| HTTP 请求、MQTT 事件 | 请求需要明确的结果；变化事件可由多个消费者订阅。 |
| 设备配置先保存再切换 | 持久化失败时不执行请求的配置变更；进程启动失败时尝试恢复旧快照。 |
| 不自动重试写入 | 超时后 PLC 可能已执行写入，重复发送会带来错误结果。 |

## 读写与并发

原始读取验证 `db`、`offset` 和 `length` 后，由设备进程为请求分配编号、发送给 C Port，并以调用方和计时器记录待完成请求。C Port 按帧顺序处理请求，回复中的编号将结果对应到原调用方。点位读取先读取必要字节，再按 S7 大端序解码。批量点位读取会合并同一 DB 内连续或重叠的区间，结果保持输入顺序。

普通写入先由 `PlcService.Point` 编码，再发送原始字节。Bool 写入由同一个设备进程串行执行“读一个字节 → 修改目标 bit → 写一个字节”；这个流程进行期间，新进入该设备进程的请求进入队列，完成后依次恢复处理。因此本服务内并发调用不会互相覆盖同一字节的其他 bit。它不是 PLC 侧事务：PLC 程序或其他客户端同时写该字节仍可能竞争。`write_points/2` 按输入顺序执行，失败时停止；已经成功的写入不会回滚。

## 订阅与事件

首位订阅者到来时立即读取；每次读取结束后再等待 `interval_ms` 安排下一轮。Block 同时只保持一次轮询请求。首次结果、值变化、错误变化和错误恢复会生成事件；不变的值或相同错误不重复发送。新订阅者会收到最近事件的快照，快照保持原 `timestamp` 和 `sequence`。详细字段与规则见 [plc-events.md](plc-events.md)。

内部事件用进程消息传送，没有确认或持久化。MQTT 适配器订阅配置中的原始 DB 流，使用每条流一个“最新事件”缓存；连接恢复后按 topic 重发当前缓存。默认 retained 发布让新 MQTT 订阅者从 Broker 获取最新状态。它不保存历史，不能保证每次变化都被离线消费者看到；QoS 1 可配置，但应用不提供端到端确认语义。

## 设备配置与生命周期

启动时优先读取设备快照文件；文件不存在时使用 `config :plc_server, :devices`，其为空或缺失时才使用 `PLC_HOST` 等旧环境变量。**存在的空快照**表示显式配置为零台设备，不会回退环境变量。设备配置可运行时添加、替换和删除，变更写入版本化 Erlang term 快照，临时文件写完后重命名覆盖。文件不可读或内容无效会阻止启动。

更新或移除设备时，等待中的请求分别收到 `:device_reconfigured` 或 `:device_removed`。已有 Block 不因设备移除而消失：下次读取报告 `:unknown_plc`，相同 ID 的设备重新添加后可发出恢复事件。设备进程和 C Port 的生命周期见 [system-architecture.md](system-architecture.md)。

## 故障处理与限制

- C Port 异常退出时，设备进程回复所有等待中的请求并退出；其监督器重启设备进程及 Port。
- 请求超时返回 `:timeout`。同一设备连续达到 `max_consecutive_timeouts`（默认 3）时，设备进程停止并重启 Port；其他等待请求得到 `{:port_timeout, n}`。收到其他 Port 回复时超时计数清零。
- C Port 在第一次实际读写时连接 Snap7。通信失败后断开其连接，下一次请求再连接；`device_status/1` 仅报告本地 Port 和最近一次 I/O，不主动检测 PLC 在线状态。
- MQTT 客户端自动重连，Block 退出后适配器重新订阅。HTTP 请求本身不重试写入。
- 内部订阅者可能积压消息；目前没有针对慢消费者的专用队列、丢弃策略或投递确认。
- HTTP 只提供明文监听；跨主机访问应通过 TLS 反向代理保护令牌和写入数据。MQTT 连接当前使用 TCP，网络隔离和 Broker 访问控制由部署环境提供。

## 验证范围

仓库测试覆盖 mock Port 的读写、位并发、故障恢复、订阅、设备配置、HTTP 路由与模拟 Broker 发布。曾在本机 Mosquitto 验证 mock PLC 的 MQTT 发布和 retained 回读，并通过本机 HTTP 端口验证 mock PLC 读取和状态查询。真实 PLC、真实 Broker 断线重连以及现场负载仍需在部署环境验证。
